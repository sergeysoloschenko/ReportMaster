## Назначение и рабочий процесс

Приложение готовит таблицы задач и рисков по отелю и апартаментам для включения в общий отчёт технического заказчика. В сферу входят Dusit, договоры HMA/Manchise, Dyer в части этих объектов, закупки, консультанты и связанные вопросы координации.

1. Последний доступный отчёт открывается автоматически. Неудачные попытки показаны отдельно в журнале.
2. Кнопка «Новый отчёт» открывает выбор завершённого месяца. Границы периода определяются по Москве.
3. Приложение берёт предыдущую утверждённую версию, читает входящие и отправленные письма за месяц, отбирает релевантные сообщения и контекст цепочек.
4. Вложения и документные ссылки из отобранных писем скачиваются; читаемый текст передаётся модели для извлечения фактов. Файлы без извлекаемого текста не считаются прочитанными.
5. Формируются краткие результаты, статусы и риски с привязкой к источникам. Продолжения связываются с прежними задачами; отсутствие новостей не означает завершение. Закрытые задачи без развития не повторяются.
6. Пользователь проверяет черновик, правит формулировки, сохраняет и утверждает версию. Только утверждённая версия становится основанием следующего периода.
7. Скачиваются Word с таблицами и ZIP с вложениями. Структура: `Задачи / номер раздела / название пункта` и `Риски / номер риска / название риска`. Недопустимые для пути символы заменяются; чрезмерно длинные названия сокращаются с контрольным суффиксом, полные названия сохраняются в индексе.

## Архитектура

- React/Vite: интерфейс в `webapp/frontend/src`; `Monthly.jsx` — месячная отчётность, `App.jsx` — вход и дополнительные режимы анализа.
- Nginx: отдаёт frontend и направляет `/api` в backend.
- FastAPI: `src/webapp/backend/app.py`; защищённые месячные маршруты — `src/reporting/routes.py`.
- `pipeline.py`: последовательная очередь обработки, отбор писем, вложения, факты, редакция и экспорт.
- `ews.py`: HTTPS EWS, NTLM; endpoint `https://post.spgr.ru/EWS/Exchange.asmx`, логин `spectrum\soloshchenko`. Используются FindFolder, FindItem, GetItem и GetAttachment. Почта не изменяется.
- `sdk.py`: официальный Python Codex SDK, авторизация ChatGPT. Luna — отбор/извлечение, Terra — предыдущий отчёт/редакция/риски. Автоматического перехода на оплату по API-ключу нет.
- `store.py`: SQLite, версии отчётов, сообщения и кеш. Утверждённые версии неизменяемы; правки создают редакцию.
- `schema.py`: проверка структуры, источников, вложений и связей с историей.
- `reference.py`, `documents.py`: разбор исходного Word и экспорт таблиц с сохранением формы образца.
- `config/project_participants.yaml`: согласованный справочник контрагентов и ролей.

Подробный алгоритм и ограничения: [monthly-reporting.md](monthly-reporting.md). Проверка дизайна: [ui-design-review.md](ui-design-review.md).

## Данные и состояние

На сервере `data`, `logs`, `config` и `.codex` подключены в контейнеры как постоянные каталоги. Пересборка контейнеров не должна удалять их.

- `data/history/reports.sqlite3`: история, источники и кеш; делать согласованную копию SQLite через backup API либо после остановки backend.
- `data/history/ews_password`: локально и на сервере, права 0600.
- `data/reference`: исходный отчёт.
- `data/mail/attachments`: документы писем.
- `data/output/history`: экспортированные таблицы и вложения по версиям.
- `.codex`: серверная авторизация ChatGPT; не публиковать и не заменять при обычном деплое.

Июль 2026 утверждён пользователем: 32 задачи и 5 рисков. Август 2026 — черновик: 46 включённых пунктов, 6 рисков, 64 задачи с учётом истории; собрано 287 писем, отобрано 184. Эти данные перенесены на Hostinger. Август не утверждён автоматически.

Три ранние неудачные попытки августа сохранены: неполный ответ отбора; завершение процесса Codex с ошибкой структуры кеша моделей; прерывание перезапуском. Они не являются новыми сбоями деплоя.

## Локальная разработка и проверки

Backend: `.venv-sdk/bin/python -m uvicorn src.webapp.backend.app:app --host 127.0.0.1 --port 8000`.
Frontend: `npm run dev --prefix webapp/frontend`.
Проверки: `.venv-sdk/bin/python -m pytest tests -q`; `npm run build --prefix webapp/frontend`.

В текущем локальном окружении зависимости Rollup установлены для x64. Проверенная сборка: `arch -x86_64 /usr/local/bin/node webapp/frontend/node_modules/vite/bin/vite.js build webapp/frontend`. Это особенность локального окружения, Docker собирается обычным `npm run build`.

## Порядок деплоя

1. Проверить изменения, создать коммит и отправить в GitHub.
2. На сервере проверить `git status --short`, сохранить резервную копию изменяемых конфигураций; данные и авторизацию не перезаписывать.
3. В `/opt/report-master`: `git pull --ff-only` из согласованной ветки.
4. На этом сервере установлен **docker-compose 1.29.2**, а не `docker compose`. Для изменения только frontend: `docker-compose build frontend`.
5. Из-за несовместимостей старого Compose с пересозданием контейнеров использовать `docker-compose stop frontend`, затем `docker-compose rm -f frontend` и `docker-compose up -d --no-deps frontend`. Томов `data` это не касается. Backend перезапускать только при изменении его кода или окружения, предварительно проверив отсутствие активного отчёта.
6. Проверить внешний `/api/health`, HTML/JS новой сборки, вход и защищённые маршруты истории/скачивания. Обычный UI-деплой не требует повторного анализа писем.
7. Для отката сохранить тег предыдущего Docker-образа перед сборкой. Вернуть этот образ под рабочий тег и пересоздать соответствующий контейнер с `--no-build`; затем синхронизировать код с согласованным Git-коммитом.

Архив конфигурации до SDK находится на сервере в `/opt/report-master-backups/before-sdk-6a3e98c0.tgz`. Это не полная резервная копия данных. Остановленный `reportmaster-backend-before-sdk` оставлен после первой миграции как резерв старого контейнера; для обычного UI-деплоя он не используется.

## Известные ограничения

- Полный расход токенов первого августовского запуска не сохранился после сбоев/возобновления. Не использовать его как измеренную стоимость типового отчёта.
- Текущий подход к анализу вложений оставлен по решению пользователя. Повторяющиеся тексты документов могут повторно попадать в модель; улучшения дедупликации отложены.
- OCR не выполняется. Вложения ограничены размером; ограничения и недоступные ссылки отражаются предупреждениями.
- «Почта настроена» в UI означает наличие конфигурации, а не непрерывную проверку доступности EWS.
- Дизайн оценён независимым агентом на 8,3/10 после двух итераций. Это не полная сертификация доступности.
